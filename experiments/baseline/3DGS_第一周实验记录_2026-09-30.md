## 3. 关键安装命令记录

以下为操作回顾，不必重复执行。安装期间已在微星 PRO B650M-B 的 BIOS 中启用 SVM，并完成 Windows 重启。

Windows PowerShell：

```powershell
wsl --install -d Ubuntu-22.04
wsl -d Ubuntu-22.04
```

Ubuntu：

```bash
sudo apt update
sudo apt install build-essential git wget python3-venv python3-pip
python3 -m venv ~/venvs/3dgs
source ~/venvs/3dgs/bin/activate
python -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128

cd ~
wget https://developer.download.nvidia.com/compute/cuda/repos/wsl-ubuntu/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb
sudo apt update
sudo apt install cuda-toolkit-12-8

export CUDA_HOME=/usr/local/cuda-12.8
export PATH="$CUDA_HOME/bin:$PATH"
mkdir -p ~/projects
cd ~/projects
git clone https://github.com/graphdeco-inria/gaussian-splatting.git --recursive
cd gaussian-splatting
python -m pip install setuptools wheel ninja plyfile tqdm opencv-python joblib
export TORCH_CUDA_ARCH_LIST="12.0"
export MAX_JOBS=2
python -m pip install --no-build-isolation ./submodules/diff-gaussian-rasterization
python -m pip install --no-build-isolation ./submodules/simple-knn
python -m pip install --no-build-isolation ./submodules/fused-ssim
```

三个扩展导入、GPU 矩阵乘法、`python train.py --help` 均已通过。上述 export 设置只对当前终端会话生效；12.0 是 GPU 计算能力，不是 Toolkit 版本。没有套用官方旧版 environment.yml，也没有在 WSL 内安装 Linux NVIDIA 驱动。

## 4. 数据输入与输出

数据来自官方提供的 T&T + DB 压缩包：

https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/datasets/input/tandt_db.zip

```bash
mkdir -p ~/datasets
cd ~/datasets
wget -c https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/datasets/input/tandt_db.zip
python3 -m zipfile -t ~/datasets/tandt_db.zip
python3 -m zipfile -e ~/datasets/tandt_db.zip ~/datasets/tandt_db
```

本次输入目录：`/home/administrator/datasets/tandt_db/tandt/truck`。

- images：场景照片；原始图像约 979 × 546 像素。
- sparse：预先计算好的 COLMAP 相机参数、位姿与稀疏点云；本次尚未自行运行 COLMAP。
- 日志读取 251 个相机，初始化点数 136029；启用 --eval 后留出 32 个测试视角。

输出位于代码目录的 output 下：

- point_cloud/iteration_N/point_cloud.ply：可供渲染的高斯模型，包含的不只是普通点云坐标。
- cfg_args：场景与渲染相关配置，不等于全部训练超参数的完整日志。
- test/ours_N/renders：测试视角的渲染图片。
- test/ours_N/gt：对应真实参考图片，按本次设置的分辨率导出。
- results.json：各指标平均值。
- per_view.json：每个测试视角的指标。

30,000 次模型文件约 486 MiB（ls -lh 显示 486M）。这些文件保存在本机 WSL 中，没有上传到个人 GitHub。普通模型 PLY 不包含完整优化器状态，不等价于可完整恢复训练的 checkpoint。

## 5. 训练、渲染与评估命令

在已激活的 3dgs 环境、代码目录中执行。以下为记录，不必重复训练。

```bash
# 短训练检查
python train.py -s ~/datasets/tandt_db/tandt/truck -m output/truck_test_100 --iterations 100 --save_iterations 100 -r 4 --data_device cpu --eval

# 低分辨率初试
python train.py -s ~/datasets/tandt_db/tandt/truck -m output/truck_7000_r4 --iterations 7000 --save_iterations 7000 --test_iterations 7000 -r 4 --data_device cpu --eval

# 原始分辨率 7,000 次
python train.py -s ~/datasets/tandt_db/tandt/truck -m output/truck_7000_r1 --iterations 7000 --save_iterations 7000 --test_iterations 7000 -r 1 --data_device cpu --eval

# 原始分辨率 30,000 次，从头训练
python train.py -s ~/datasets/tandt_db/tandt/truck -m output/truck_30000_r1 --iterations 30000 --save_iterations 7000 30000 --test_iterations 7000 30000 -r 1 --data_device cpu --eval

python render.py -m output/truck_7000_r1 --iteration 7000 --skip_train
python render.py -m output/truck_30000_r1 --iteration 30000 --skip_train
python metrics.py -m output/truck_7000_r1 output/truck_30000_r1
```

参数含义：-r 4 将宽高各缩小为四分之一；-r 1 保留原始尺寸。--data_device cpu 将输入图像保存在系统内存，训练仍使用 GPU。--eval 留出测试视角。

## 6. 定量结果

以下为对保存的 PNG 图片运行 metrics.py 后得到的 32 个测试视角平均指标：

| 实验 | PSNR ↑ | SSIM ↑ | LPIPS ↓ |
|---|---:|---:|---:|
| truck，r1，7000 次 | 23.9805965 | 0.8529009 | 0.1952568 |
| truck，r1，30000 次 | 25.4635582 | 0.8845079 | 0.1421366 |

PSNR 提升约 1.483 dB，SSIM 提升约 0.0316，LPIPS 降低约 27.2%。这是当前设置下的本机复现结果，不等同于复现论文全部基准成绩。

r4、7000 次训练日志中的测试 PSNR 为 26.2613 dB；由于分辨率不同，不将其与 r1 指标直接比较。r1、7000 次训练时记录的 PSNR 为 23.9902 dB，与保存 PNG 后的评估结果略有不同；表格统一采用 metrics.py 结果。

时间与资源记录：

- r4、7000 次：进度条显示约 1 分 28 秒；从日志开始到 Training complete 约 1 分 35 秒，两者计时范围不同。
- r1、7000 与 30000 次：完整训练耗时未记录。
- 各次训练峰值显存：未记录。初始 nvidia-smi 的桌面显存占用不能充当训练峰值。

## 7. 视觉观察与问题记录

主体轮廓、木板纹理、掉漆和轮毂得到较完整还原。树叶、地面、车底仍有模糊；渲染中车厢后方出现 GT 中没有的白车。可能与拍摄期间背景运动有关，尚未检查其他输入视角来验证原因，不能作为确定结论。

| 问题 | 诊断与处理 | 结果 |
|---|---|---|
| WSL2 无法启动，HCS_E_HYPERV_NOT_INSTALLED | 任务管理器显示虚拟化禁用；在 BIOS 启用 SVM 并重启 | Ubuntu 与 GPU 访问正常 |
| 官方环境文件为旧 Python/PyTorch/CUDA | 使用独立 venv、PyTorch 2.7.1 cu128 与 Toolkit 12.8 | 实际 GPU 运算、扩展编译通过 |
| Git clone 的 GnuTLS 连接中断 | git ls-remote 检查连通性，成功后重试递归克隆 | 主仓库与子模块下载完成 |
| 数据下载疑似中断 | wget -c 提示已完整下载；Python zipfile 完整性检查 | 检查通过、成功解压 |
| r4 输出和 GT 都模糊 | 宽高均被缩小；改为 r1 并保留旧实验 | 提高输出分辨率 |
| Tensorboard not available | 未安装可选日志工具 | 不影响训练，未生成 TensorBoard 曲线 |
| metrics.py 只显示 Unable to compute metrics | 单独测试 LPIPS，暴露 Connection reset by peer | 确认权重下载的网络问题 |
| raw.githubusercontent.com SSL 连接失败 | Windows 浏览器下载官方 vgg.pth；torch.load(weights_only=True) 验证五组权重，再复制缓存 | 两组完整指标计算成功 |

LPIPS 权重缓存处理：

```bash
cp /mnt/c/Users/Administrator/Downloads/vgg.pth ~/.cache/torch/hub/checkpoints/vgg.pth
```

约 8 KB 的 vgg.pth 是 LPIPS 的小型权重，区别于已自动下载的约 528 MB VGG16 权重。启动时的 localhost 代理提示尚未通过系统配置消除，本次用浏览器下载解决了该具体文件的获取问题。
