# Read-only COLMAP metadata capacity inventory

This is a descriptive inventory of the original Truck `sparse/0/points3D.bin`, `images.bin`, and `cameras.bin`. It is not a method threshold, method success/failure, measured method throughput, artifact detector, or causal/novelty result. No pass line will be introduced after observing these distributions. In particular, SfM visibility tracks are selected reconstruction observations, not certificates that other space is absolutely empty.

- The official repository `scene/colmap_loader.py` is imported **directly by file path**, with no import of the `scene` package. Its original camera/image binary readers are used. Its point reader discards point IDs and tracks after parsing, so the inventory preserves these fields using that same file's `read_next_bytes` binary primitive and `Point3D` record type, following the identical 43-byte point header and eight-byte `(image_id, point2D_idx)` track entry format. The official file is not edited.
- The split is fixed before the inventory: sort all registered image names, hold out every eighth name starting at rank zero, and treat the remaining images as training, matching the existing Truck evaluation split. Expected identity is 251 total / 219 train / 32 heldout. All names, IDs, and split assignments are archived. No previously viewed test ROI, teacher residual, or pixel value influences this split or any track grouping.
- Total track length is the number of on-disk entries per point. Training track length counts entries whose image IDs belong to that fixed training set. Distinct training-image count is also reported to expose any duplicate image entries. Counts at least 2/3/4/6 are **descriptive bins only**, not acceptance conditions or track-selection rules.
- Training camera-pair shared-track counts use unique known training image IDs per point. Every point contributes regardless of its reprojection error, depth, finite XYZ, or any ROI; duplicate image entries count once per point/pair. Bad references and consistency problems are separately counted, not silently repaired or presented as a filtered clean sample. The pair distribution includes all unordered training camera pairs, including zero-shared-track pairs. No test pair is used to calibrate anything.
- Stored COLMAP reprojection-error quantiles are reported in their original metadata units; no new projection fit or threshold is computed. Per-training-image associated observations come from `images.bin` point IDs. Actual depth is the z component of the original official `qvec2rotmat(qvec) @ XYZ + tvec`; the quaternion is not refit or renormalized. Strict `z>0` is reported among finite evaluable observations and also relative to all associated observations, with bad IDs/nonfinite cases separately accounted for.
- Images and their stored sparse observations are parsed as metadata only. Stored XY coordinates may be checked for finiteness/record consistency; no photo/JPEG, feature descriptor, image feature extraction/matching, GT mask, rendered image, model checkpoint, or Gaussian parameter is read or created. No spatial image/scene region is selected or screened; all spatial-group capability beyond these unfiltered metadata summaries remains untested.
- Camera metadata uses the original 1957x1091 COLMAP domain. The previously loaded native photos were 979x546, but this inventory does not reopen or sample them and never uses stored COLMAP XY to index native pixels. A future point-to-native-array conversion must separately align the native `ndc2Pix` convention (scaled boundary principal coordinate minus 0.5); no such conversion is performed here.
- Empty records, unknown camera/point/image IDs, out-of-range track observation indices, mismatched reciprocal point IDs, duplicate track records, and nonfinite data are recorded descriptively. Invalid-record counters are bookkeeping and do not become scientific gates.
- The inventory is CPU-only, numerical threads limited to one, with one authorized execution and no automatic retry/overwrite. The three original bins, official loader source, inventory script, and this note are SHA-256 checked before and after. Raw per-point length/error vectors and the training pair-count matrix are saved for independent recounting.

Limitations: sparse tracks are neither dense visibility nor guaranteed unoccluded rays; SfM has selection bias, incomplete coverage, uncertain geometry, and finite reconstruction error. Positive reconstructed observation depth only checks this existing coordinate geometry. None of these summaries establishes a usable background/empty-space witness, a pruning opportunity, or artifact removal quality. No parameter fitting, pruning, native render, GPU operation, or training is performed.
