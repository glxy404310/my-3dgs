# Native backend preparation assumptions

This file records implementation choices for `scripts/experiments/shared_coordinate_native.py`. It is not an execution contract and selects no views, patches, matching thresholds, finite-difference steps, acceptance gates, or run directory. Preparation is limited to source inspection and `py_compile`; no model loading, rendering, GPU work, training, or scientific run is authorized in this preparation task.

## Inputs and frozen state

- The backend accepts only iterations 7000 and 30000 from the existing `repo/output/truck_30000_r1` run and the existing `/home/administrator/datasets/tandt_db/tandt/truck` source. It does not search for a latest checkpoint or initialize a model from a point cloud.
- It uses native `Scene` and `GaussianModel(3, 'default')`, with `resolution=1`, `resolution_scales=[1.0]`, `images='images'`, `depths=''`, `white_background=False`, `train_test_exp=False`, `data_device='cpu'`, `eval=True`, and `shuffle=False`. Training cameras are sorted lexicographically by their complete native `image_name`, including its extension. The full training list is returned; this helper chooses no subset.
- Native `loadCam` derives resolution from the actual image size, not COLMAP metadata dimensions. Thus resolution 1 means the existing source JPEG dimensions (previously reported as 979 by 546), not the 1957 by 1091 metadata dimensions. This preparation does not reopen images to verify dimensions.
- All tensor attributes of the loaded Gaussian model, including any tensors in dictionaries/lists/tuples, have `requires_grad=False`. Both `optimizer` and any `exposure_optimizer` must be absent or `None`. The helper never calls `training_setup`, `restore`, `save`, `save_ply`, or an optimizer.
- The native pipeline is fixed to `convert_SHs_python=False`, `compute_cov3D_python=False`, `debug=False`, and `antialiasing=False`. Rendering uses black GPU background, scaling modifier 1, combined native SH, and explicit `use_trained_exp=False`.

## Pose convention

`T_cw` means the 4 by 4 column-vector camera-to-world matrix, obtained by inverting `camera.world_view_transform.T`. Native Camera stores the world-to-camera matrix transposed for the renderer. The six-vector order is `(rx, ry, rz, tx, ty, tz) = (omega_x, omega_y, omega_z, v_x, v_y, v_z)`, with rotation in radians and translation in the model's world units. The update is exactly

```
T_cw_new = T_cw @ exp([[skew(omega), v], [0, 0]])
R_delta = I + A W + B W^2
V       = I + B W + C W^2
t_delta = V @ v
```

Here `A=sin(theta)/theta`, `B=(1-cos(theta))/theta^2`, `C=(theta-sin(theta))/theta^3`, with Taylor expansions near zero. Right multiplication means each one-axis translation follows a column of the original C2W rotation and each one-axis rotation acts in the original camera frame. A general mixed twist uses the true SE(3) exponential, including its V matrix. The per-axis triplet takes caller-supplied positive steps and renders the unchanged center plus separate negative and positive perturbations of exactly one coordinate. It never chains a positive perturbation from the negative camera.

Each perturbed camera is a new pose-only `SimpleNamespace`. `R`, `T`, `world_view_transform`, `projection_matrix`, `full_proj_transform`, and `camera_center` are rebuilt. The effective loaded C2W already includes any native normalization; copied metadata therefore uses `trans=0`, `scale=1`. Ground-truth image/mask tensors are deliberately not attached to the copy; callers use the original camera for those. The original camera and all Gaussian tensors are read only during perturbation/rendering.

## Why native Scene loading is read only under these preconditions

The inspected native repository is `/home/administrator/projects/gaussian-splatting`.

- `scene/__init__.py:51` places the `input.ply` and `cameras.json` writes under `if not self.loaded_iter`. Explicit 7000/30000 selects the `load_ply` branch at lines 77–82, bypassing both writes and `create_from_pcd` at line 83. `Scene.save` is a separate method at line 85 and is never called.
- `scene/dataset_readers.py:208` contains a separate `if not os.path.exists(ply_path)` conversion path for `source/sparse/0/points3D.ply`; line 214 calls `storePly`. The helper requires that file to exist **before importing or constructing Scene**, and checks its SHA-256 before/after loading. Missing cache is a hard error; it is not generated by the helper. This protects the normal inspected native path, not a hostile concurrent process removing the cache between the precheck and Scene's check.
- `scene/gaussian_model.py:263` uses `PlyData.read`; lines 307–312 construct new CUDA Parameters. `train_test_exp=False` skips exposure loading. Construction and freezing act on a newly created in-memory GaussianModel; there is no write to the checkpoint PLY.
- `scene/cameras.py:86–89` builds newly allocated view/projection matrices and center. The helper follows the same transpose, matrix multiplication, and center-inverse convention without setting any field on the original Camera.
- `gaussian_renderer/__init__.py:18` exposes the native renderer; lines 43/46 consume view matrix and center. The renderer creates temporary screen-space tensors at line 26, with no model update. The helper wraps the full call in `torch.no_grad()` and explicitly disables the exposure branch at line 113.

The checkpoint source PLY and the COLMAP point cache are SHA-256 checked around load. `model_hash` is available for caller-owned before/after guards on any loaded model; it hashes names, dtypes, shapes, bytes of the six core Gaussian tensors plus any exposure tensors, and active/max SH degree. This is intentionally not the legacy six-tensor-bytes-only digest from the diagnostic script. Full parameter hashing copies tensors to CPU and must be included in the eventual time budget. The render helper checks frozen state but does not repeat a full parameter hash around every render.

## Known limits and pending witnesses

- Static compilation does not validate native imports, extension ABI, actual model dimensions, GPU memory, runtime, or render reproducibility. No such runtime result is claimed here.
- The mathematical SE(3) calculation is CPU float64; native rasterizer matrices use the original camera tensor dtype (normally float32). Tiny finite-difference steps can be lost in float32 conversion, and visibility/sorting changes can make derivatives nonsmooth. Step selection and tool-noise/zero-pose/axis-sign witnesses belong to the main contract.
- Only the native renderer is used; no image warp, matching, fitting, or RGB interpolation is supplied here. Native output already applies its normal RGB clamp.
- CPU RGB is a detached contiguous `(3, H, W)` torch tensor. `return_native=True` also retains the native renderer dictionary and therefore GPU buffers; the caller owns its lifetime. Neither option writes images or files.
- Loading native Scene constructs train and test cameras, including CUDA pose tensors, even with image data on CPU. Loading both checkpoints separately duplicates camera state unless the caller releases one. No memory/time feasibility is certified.
- `FrozenCheckpoint` freezes the bundle's attribute bindings, not the mutable Python objects it contains. A caller can still mutate a Gaussian, Camera, pipeline, or tensor outside this helper. Before/after model/PLY hashes remain necessary evidence in the main program.
- Source files are not hard-pinned by this preparation helper; the final root contract must call `native_source_hashes` and compare against its locked manifest before calling the loader. The returned source hashes are additional load-time evidence.
