# Assumptions fixed before dependent code

1. Cached NanoGS GT/teacher pixels and exact 33 CAMERAS remain the reference. Their source/hash provenance is checked before/after actual execution. Only metadata may be read during preparation.
2. The original native GaussianModel is used for both workers so loader, SH ordering, opacity/scale/rotation activation and frozen model bytes match. This does not claim to reproduce Speedy training or pruning.
3. The unmodified official Speedy renderer can be imported by an alias while its `scene`/`utils` references resolve to the pinned native model/SH helpers. The fixed configuration never uses Python SH evaluation; native model attributes implement the accessed API. Its rasterizer package resolves to the actual successful isolated build.
4. Official Speedy's scores=None allocates zeros_like(opacity) inside each render. The measured adapter clamps RGB to [0,1], then converts the existing boolean visibility_filter via `.nonzero()` to native index semantics; it does not recompute `(radii>0)`. This avoids counting omitted nonzero synchronization as tile acceleration. No clipping or support override is introduced in CUDA, and official source bytes remain unmodified. Other fixed official costs (native invdepth versus Speedy kernel_times, internal event synchronization) remain disclosed inside complete-forward timing, not an isolated CUDA-subkernel benchmark.
5. Native 016 camera+loader parity is a tool gate, not a Speedy quality gate. Quality teacher rows reuse all 33 cached teacher images; only one new native parity raw is saved. New raw files total 34, references 66, combined manifest 100 files.
6. Both workers can keep one full teacher on the 12GB device under <=3 GiB allocated each. The sampled process-tree host RSS and sum of worker peaks are enforced; allocation failure produces an incomplete result, never a smaller model or lower-resolution rescue.
7. Sequential acknowledged requests, shared timeout process group and shared 225-second monotonic deadline prevent the two workers from rendering concurrently. Loading/checks/cleanup are also requested sequentially. Both models stay resident during interleaved timing; idle workers do no GPU work.
8. Existing SH8 evaluate.py is imported read-only only for lossless camera reconstruction, pixel loading, RGB PNG conversion and CPU metric functions; its experiment main is never invoked. Native model/hash/provenance helpers are likewise read-only pinned imports. No Scene instance is created.
9. Finite positive MSE is expected for real GT images; any zero-MSE infinite PSNR is represented explicitly and makes finite-difference quality gate unavailable rather than fabricated. SSIM/PSNR loss gates use signed teacher-minus-Speedy values; improvements do not become absolute penalties.
10. Two fixed names, ten repeats, 32 views, all resource budgets and four quality plus two timing gates are immutable before actual images/timings are observed. New engineering control success is not scientific novelty, and historical FAILs remain unchanged.
