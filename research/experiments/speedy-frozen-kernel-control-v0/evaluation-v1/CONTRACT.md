# Frozen official Speedy-Splat kernel control, v1

This is a known engineering control, not an innovation claim. One attempt only; no training, optimizer, backward, pruning, parameter changes, source patches, retries or result-dependent changes. Preserve all old ADC/NanoGS FAILs. Preparation may read code and JSON metadata, and may run tiny CPU formula/protocol checks; it must not read scientific arrays/models or initialize CUDA.

Require the original teacher model hash `b6b71329ebaec4c88887bd2320a7b67fa9189c20af3db54bcdb7824164a3a8f0` in both workers.

The CLI requires six actual path/SHA256 pairs: build RESULT/SUPERVISOR/HOST_EXTERNAL and tiny-witness RESULTS/SUPERVISOR/HOST_EXTERNAL. Import-only success is insufficient. Validate actual successful stages, one-shot external clocks (build <=180 s; witness <=60 s), synthetic 3F/0B/0updates/0real-model witness and actual private wrapper/extension identities. No placeholders, invented build identity, or prepared-only readiness certificate.

Use a stdlib controller and two persistent isolated workers. Both load the same original native GaussianModel; only the rasterizer and official renderer differ. Native and private Speedy packages share a name and must never coexist in one worker. No module eviction. Deduplicate the native repository path before imports; keep strict provenance checks. Speedy loads the unmodified official render function by a separate module alias, backed by its private extension. Official commits: main `34c45c6d9b8bd6110231864f2f358b6d3abbf73d`, rasterizer `b38abb6da7a7217999f8c5ec0e9219284464ffe0`, GLM `5c46b9c07008ae65cb81ab79cd677ecc1934b903`. The official Speedy render allocates its default zero scores and consumes its three-return API. Inside the measured adapter, add the matching final RGB clamp, then turn Speedy's existing boolean visibility_filter into `.nonzero()` indices, matching native output semantics without a repeated `(radii>0)` operation. Sources remain unmodified. Other fixed official differences (native invdepth output versus Speedy kernel_times and internal event/synchronization behavior) remain part of full-forward cost, so this is not an isolated CUDA-subkernel benchmark. Do not use Speedy's internal kernel_times as benchmark data.

Both conditions use SH3, native scale/rotation covariance, scaling modifier 1, black background, no exposure, AA false (Speedy has no AA setting), no SH precompute, no custom near plane/support/clipping. Speedy's ellipse support differs from native 3-sigma support; do not preclaim lossless or pixel equality.

## Fixed execution and timing

Workers execute only upon controller request, and acknowledge only after CUDA completion. They remain loaded and idle between requests; no overlapping GPU work. Native makes one quality parity render of `000016.jpg`, compared with cached teacher pixels at maxabs <=2e-5 and saved as real raw+PNG. Speedy renders all 33 quality images and saves raw+PNG. Each worker then performs 8 warmups using the first 8 test cameras. Ten repeats alternate AB and BA (A=native, B=Speedy), 5 each. Every condition/repeat renders the full 32 test views in original ascending recorded order. No dropped frames/outliers. Exact totals: native 329F (1+8+320), Speedy 361F (33+8+320), total 690F, 0B, 0updates.

For every timed frame: CUDA pre-synchronize outside wall; start wall; record CUDA start event; call the full official forward plus matching final clamp; record stop event; synchronize stop; stop wall. RGB CPU transfer, validation, hashing, I/O, metrics, model/camera checks and RPC waiting are outside both timing windows. Record external synchronized wall and CUDA-event milliseconds separately. Events are reused per worker; recorded kernel_times never replaces them. Per-view latency is the median of its 10 measured repeats. Main speed statistic is the mean of 32 per-view median synchronized-wall latencies. Also compare each paired repeat's full-32 mean wall.

## Locked quality and keep/stop rules

Recompute teacher/Speedy quality from saved pixels with existing CPU float64 Gaussian11/sigma1.5/constant0/population SSIM. Exactly 66 metric rows, 32-test means, each arm's own GT worst-4 MSE mean, all 33 per-view signed deltas. Separate exact RGB equality and teacher fidelity. Do not normalize scores or soften old thresholds.

Quality near-equivalence requires all: teacher-minus-Speedy mean GT PSNR <=0.1 dB; mean GT SSIM <=0.001; Speedy/teacher own GT-tail4 mean MSE <=1.05; worst single test teacher-minus-Speedy PSNR <=0.3 dB. Keep this engineering control only if quality passes AND mean per-view-median synchronized wall decreases at least 10% AND Speedy full-32 block mean wall is lower in at least 9 of 10 repeats. Otherwise STOP this control and retain actual numbers, without tuning or retry. These are new-control gates, not revisions of ADC/NanoGS gates. Independent audit must confirm artifacts before a final accepted decision.

Panels are actual pixel concatenations GT|teacher|Speedy: fixed 016/017/105 full and top220 (6), plus four worst test SSIM losses (teacher minus Speedy, descending; view-name tie break; keep negative losses) full (4), exactly 10. Fixed/exploratory labels remain distinct even on duplicate views.
